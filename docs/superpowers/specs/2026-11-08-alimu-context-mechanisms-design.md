## Predeclared stages
A: six original families (LSTM64, BiLSTM32, GRU, BiGRU, CNN-Transformer, CNN-TCN), windows 40/80/160/320, three seeds. 72 slots. Exact source controls may be reused only after data/config/support/checkpoint hash validation. Match original 80-epoch AdamW, patience15 recipe. Select windows on mean VALID only.
B: five backends (LSTM, GRU, BiGRU, Transformer, TCN), common causal CNN and token LayerNorm, 320 points, lookahead0/6, three seeds, plus full-context BiGRU/Transformer (36 slots). All use the same available prefix ending at t+lookahead. Unidirectional backends use delayed readout; BiGRU uses forward state plus a bounded backward scan; Transformer uses causal attention then delayed readout. A full-context branch uses the remaining window. Perturbation tests in train and eval must certify each limited-lookahead model. Original symmetric CNN has six future points; do not call it causal. All recurrent states reset per window. This is a finite-window causal comparison, not an unbounded streaming state benchmark.
C: GRU backend, causal frontend, fixed RF13: depth1/k13/width68 versus depth3/k5/width64, crossed with BN/token-LN/no-norm and GELU/identity (12 configs). Widths keep total parameters near each other; report residual width/capacity limitation. Depth3/k5/dilation2 and4 vary RF25/49 with identical parameter count. Depth3/k1 adds pointwise control (capacity changes; do not call it a pure RF intervention). Three seeds. The depth3/k5/LN/GELU base reuses B GRU-lookahead0. 45 slots including three reuses. BN training mixes temporal information; only LN/no-norm cells can support strict training-causality claims.
D: seven families (CNN-LSTM64, CNN-GRU, CNN-BiGRU, CNN-Transformer, CNN-TCN, ordinary Transformer, Informer adapter), fixed320, exactly three predeclared LR/dropout candidate packages per family with first seed. 40 epochs, patience10, same optimizer/scheduler/data/batch size. Select one package by VALID, then train the other two seeds (35 slots). Equal candidate/epoch budget, not equal wall time or parameters. Report actual costs. Adapter is the repository's ProbSparse/distilled IMU regression implementation, not an official reproduction claim.
E: three folds leaving out one LOW device. TRAIN/VALID contain only the other two devices on their respective original recordings; TEST contains only the held device on dyn08/09. Both physical recording IDs and device labels are disjoint from TRAIN/VALID. Three fixed-recipe families CNN-GRU/CNN-BiGRU/Informer, three seeds, 40 epochs, patience10 (27 fits). Use the predeclared common base recipe, never an all-device tuned selection, for this strict test. Frozen train normalization per fold, affine baseline fitted only on TRAIN. No fold uses held device VALID to select hyperparameters.
